## 0. 분석 방법과 한계 (먼저 읽어주세요)

이 문서는 **외부 공개 정보(스토어 설명, 공식 사이트 노출 문구, 사용법 리뷰 글, 커뮤니티 게시판 제목)** 를 기반으로
배달판 앱의 기능을 역추적한 것입니다.

- 앱을 직접 설치·실행하거나 APK를 디컴파일해서 검증하지는 않았습니다.
- 현재 작업 환경의 네트워크 정책상 `baedalpan.com` / Google Play / App Store 페이지 직접 조회가 차단(403)되어,
  검색 결과 요약 수준의 정보에 의존했습니다.
- 따라서 아래 기능 목록은 **"확인됨"과 "추정"을 구분해서 표기**했습니다.
  `[확인]`은 공개 문구에 명시된 것, `[추정]`은 서비스 구조상 존재할 가능성이 높은 것입니다.

정확도를 더 올리려면: 실제 앱 설치 후 화면 캡처, 또는 웹 버전(`www.baedalpan.com`)의 DOM/네트워크 트래픽 관찰이 필요합니다.

## 1. 서비스 정체성

**배달판은 "배달 라이더용 업무 기록 + 수익 관리 가계부 + 라이더 커뮤니티"를 합친 서비스입니다.**

| 항목 | 내용 |
| --- | --- |
| 타깃 사용자 | 배민커넥트·쿠팡이츠·요기요·일반대행을 **동시에/교차로 뛰는 배달 라이더** |
| 핵심 가치 | 여러 플랫폼에 흩어진 배달 건수·수입·지출을 **한 곳에 모아 실수익을 파악** |
| 부가 가치 | 오토바이 정비 이력 관리, 고객 피드백 기록, 지역·주제별 라이더 커뮤니티("배달판 카페") |
| 슬로건성 문구 | "전국 라이더 모임의 시작" — 도구 + 커뮤니티 양축 지향 |
| 공식 웹 | `www.baedalpan.com` (웹 우선, 앱은 웹을 감싼 형태) |
| Android 패키지 | `com.baedalpan.www.twa` |

### 1.1 중요한 구조적 특징: 웹 우선 + TWA 래핑

Android 패키지명이 `com.baedalpan.www.twa`로 끝납니다. **TWA = Trusted Web Activity**,
즉 네이티브 앱이 아니라 **웹사이트(PWA)를 안드로이드 앱 껍데기로 감싼 형태**입니다. 이로부터 추론되는 사실:

- 실제 로직·화면 전부가 웹(`www.baedalpan.com`)에 존재하고, 앱은 브라우저 창을 풀스크린으로 띄우는 얇은 껍데기입니다. `[확인 - 패키지명 근거]`
- 웹과 앱의 기능이 **완전히 동일**하며, 스토어 심사 없이 즉시 배포/수정이 가능합니다. `[추정]`
- 반대로 **네이티브 역량은 제한적**입니다: 백그라운드 위치 추적, 정교한 푸시, 오프라인 입력, 홈 위젯, SMS/알림 파싱 등이 사실상 어렵습니다. `[추정]`
- 즉 배달판의 데이터 입력은 **자동 수집이 아니라 라이더의 수동 입력**에 의존하는 구조입니다. `[확인 - 사용법 안내가 "배달 완료 후 기록을 입력"이라 명시]`

### 1.2 이름이 겹치는 다른 앱과의 구분

스토어에서 "배달판"으로 검색하면 아래처럼 **키워드만 차용한 별개 앱**들이 함께 노출됩니다. 분석 시 혼동 주의:

- `배달 장부 - 배달판, 배달라이더 수입/지출 관리` (iOS)
- `달린만큼 - 배달판, 배달일지, 배달라이더 수입 관리` (Android, `com.huhjin.dalrinmankeum`)
- `배달트래킹 - 라이더 수입 관리` (iOS)

→ "배달판"은 이 카테고리에서 **일반명사화된 검색 키워드**가 되어 있습니다. 경쟁이 치열하고 진입장벽이 낮은 영역이라는 신호입니다.

## 3. 종합 평가

### 3.1 강점

1. **멀티플랫폼 통합 기록** — 배민/쿠팡이츠/요기요/대행을 한 화면에서. 단일 플랫폼 앱은 절대 제공하지 않는 관점.
2. **도구 + 커뮤니티 결합** — 기록 앱의 이탈률 문제를 커뮤니티로 방어.
3. **가입 마찰 최소화** — 카카오 원탭. 라이더 대상 서비스에 맞는 현실적 선택.
4. **정비 기록** — 경쟁 가계부 앱 대비 실질적 차별점.
5. **웹 우선(TWA)** — 개발/배포 비용이 낮고 iOS·Android·PC를 한 코드베이스로 커버.

### 3.2 약점 및 기회 (재구현/개선 시 우선순위)

| 우선 | 문제 | 개선 방향 |
| --- | --- | --- |
| ★★★ | **전부 수동 입력** → 하루 40건 뛰고 밤에 앉아 입력하는 건 지속 불가. 이탈의 1순위 원인 | 플랫폼 정산 문자/알림 파싱, 정산 내역 캡처 OCR, CSV 업로드 임포트 |
| ★★★ | 세무 대응 없음 | 종합소득세용 연간 수입/경비 리포트, 경비 항목 분류, CSV·PDF 내보내기 |
| ★★☆ | TWA 한계로 푸시·오프라인·위젯 부재 | 핵심 입력 화면만 네이티브 셸 + 로컬 캐시, Web Push 또는 앱 전환 |
| ★★☆ | "시간당 실수익" 등 의사결정 지표가 전면에 없음 | 홈 대시보드에 시간당/건당/km당 수익 + 목표 달성률 상시 노출 |
| ★★☆ | 커뮤니티가 전통 게시판 구조 | 지역 자동 태깅, 실시간 콜 상황 피드, 이미지 첨부, 알림 구독 |
| ★☆☆ | 데이터 백업/기기 이전 불안 | 계정 기반 클라우드 동기화 명시, 내보내기 제공 |
| ★☆☆ | 이름 검색 경쟁 심함 | 커뮤니티(고유 자산) 중심 브랜딩 강화 |

## 4. 역설계한 데이터 모델 (재구현 참고)

```
User            id, kakao_id, nickname, created_at
UserPlatform    user_id, platform(BAEMIN|COUPANG_EATS|YOGIYO|AGENCY), is_active, sort_order
Vehicle         id, user_id, type(BIKE|CAR), model, current_odometer

DeliveryLog     id, user_id, work_date, platform,
                order_count, income_amount,
                distance_km, work_minutes, memo
                -- (user_id, work_date, platform) 복합 유니크

Expense         id, user_id, spent_at, category(FUEL|MEAL|MAINTENANCE|INSURANCE|ETC),
                amount, memo

Maintenance     id, user_id, vehicle_id, serviced_at, item,
                amount, odometer_km, next_due_km, next_due_at

Feedback        id, user_id, work_date, platform, content, sentiment

CafePost        id, author_id, board(FREE|NEWS|QNA|REGION), region_code,
                title, body, view_count, like_count, created_at, deleted_at
CafeComment     id, post_id, author_id, body, created_at
```

### 파생 지표 계산식

```
순수익(기간)      = Σ DeliveryLog.income_amount − Σ Expense.amount
시간당 수익       = 순수익 / (Σ work_minutes / 60)
건당 단가         = Σ income_amount / Σ order_count
km당 수익         = 순수익 / Σ distance_km
플랫폼 비중       = 플랫폼별 order_count / 전체 order_count
다음 정비 예상일   = 최근 정비 odometer + 평균 정비 간격(km) 도달 예상 시점
```

## 5. MVP 재구현 범위 제안

**Phase 1 — 기록의 핵심 (2~3주)**
- 카카오 로그인, 활동 플랫폼 선택
- 캘린더 홈 + 일별 기록 입력(플랫폼별 건수/수입, 거리, 시간)
- 지출 입력(주유비/식비/기타)
- 일·주·월 통계 + 시간당 수익 카드

**Phase 2 — 차별화 (2주)**
- 정비 기록 + 주행거리 기반 다음 정비 예측
- 고객 피드백 기록
- CSV 내보내기 (세무용)

**Phase 3 — 리텐션 (3주+)**
- 지역 태그 커뮤니티, 뉴스 보드
- 정산 문자/캡처 자동 파싱 (수동 입력 제거)
- 목표 설정 + 달성 알림
